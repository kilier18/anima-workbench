## 1. 三层管线

```
① 理解填槽（LLM）
   中文/半中半英 → 结构化槽位：who / act / pose / place / light / cloth / expr / count / camera
   模型只填槽，不拼串；槽位定义在 planner.SLOT_SYSTEM（12+ 条硬规则）

② 确定性渲染（代码）
   槽位 → 标签，按固定顺序拼：质量 → 角色 → 动作 → 身体 → 衣着 → 姿势 → 体液 → 人数/角色 → 机位/取景 → 表情 → 场景
   同一槽位多次出现只保留一次；非法写法丢（_drop_unknown）

③ 体检清理（规则）
   减法（后入/乳交/口交/腿交/女女/机制/扶她/事后/催眠）→ 冲突清理（体位/机位/取景/衣饰/人数）
   → 分级门（tierGate）→ 打码补正（censFix）→ 催眠补正（hypnoRule）
```

**为什么要有 ②③**：LLM 会写好看的废话（权重括号、`4k, masterpiece, ultra detailed` 堆叠、同义互斥体位）。渲染与规则负责把这些"擦干净"，模型只做它擅长的部分。

**六条写法规则**

1. 先写**谁**（角色中文名，库里 2390 个都认别名），再写**做什么**，最后写**怎么拍**。
2. 一个动作一个动词，不要叠三个近义动词（`抽送/顶入/冲刺` 会让底模拼姿势）。
3. 想要减法就别补细节：后入写"后入"就够，不用再解释"手撑在床上"。
4. 场景写地点 + 光线（`教室 夕阳` / `浴室 顶灯`），天气只在室外写。
5. 表情只说强弱（`害羞` / `爽到失神`），不要指定具体眼型词。
6. 中文里夹 tag 也认：`灵梦 all_fours from_behind` 会保留 tag 并补角色。

## 4. 扩库方法论

1. **先查词表再写**：`_setup/danbooru.csv` 里没有的写法一定丢，别凭印象造（`pussyjob`、`hot_wax`、`facesitting`、`squirting` 都不存在）。
2. **优先高热度词**：同义里选计数高的（`doggystyle` 30422 > `sex_from_behind` 常见组合）。
3. **一个条目一个主位**：修饰位（`all_fours + sex_from_behind`）可以并存，主位（`missionary` vs `cowgirl_position`）互斥。
4. **机制类去男性**：触手/机械场景写 `1boy` 会画出多余男人。
5. **扶她禁 `sex`**：`penis + sex` 在 danbooru 几乎必然绑定 `1boy`。
6. **事后必须带体液**：`cum_in_pussy / cumdrip / cum_on_body` + `pussy_juice`，否则画面没有"事后感"。
7. **稳定性写进 note**：某个写法 3 次里只成 1 次，就标"低"，别当默认选项。

### 8.5 双人池与脱衣层（2026-11-14）

**为什么要单独的 `duo` 类**
原来只有 `duo_daily / duo_flirt / duo_male` 三个池混在「辅助」里，`qScene` 下拉也没有双人项，

1. **数据层**：扩建前 9 个 R18 池里带脱衣/露出词的条目是 **0–3 条**（`solo_sex 0/55`、`yuri_sex 0/55`、

2. **代码层**：`cut(FULLGARB)` 是**单词精确匹配**，而新角色卡的服装是**词组**
